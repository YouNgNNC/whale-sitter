# whale-sitter 项目规划方案（ROADMAP）

> 本文档记录 whale-sitter 的定位、需求评估、关键决策与版本路线图。
> 建立时间：2026-08-14

## 1. 项目定位

**一句话**：帮助 DeepSeek Harness（dsh）用户省事的 Windows 小工具——管服务、装环境、答疑诊断。

- ✅ **做**：dsh web 服务的启动/停止/状态监控、环境一键安装、诊断辅助
- ❌ **不做**：替换 dsh 的 web UI（那是 DeepSeek 的原生强项，也已有社区界面版，小工具不做不自量力的事）

## 2. 需求评估（四个优化方向的结论）

用户提出的四个方向，评估结论如下：

| 方向 | 结论 | 理由 |
|---|---|---|
| ① 小白一键下载安装 dsh | ✅ **采纳**（v1.0.0 已实现） | 安装门槛是最劝退的一环，价值最高；便携 Node 免 UAC 可全程不碰命令行 |
| ② 界面美观优化 | ✅ **采纳**（v1.0.0 已实现） | 小工具的门面；采用"跟随系统明暗主题"方案（用户选定） |
| ③ 辅助引导（帮不会用的用户） | ✅ **采纳**（v1.0.0 已实现） | 一键诊断 + 智能状态 + 日志入口，降低求助成本 |
| ④ 完整独立桌面 UI（WebView2 套壳） | ❌ **放弃** | web UI 是 DeepSeek 原生强项，套壳做不过别人；保持小工具定位 |

## 3. 关键决策记录

| 决策点 | 选择 | 原因 |
|---|---|---|
| 技术栈 | C# WinForms 单文件 + Windows 自带 csc | 零第三方依赖，`build.bat` 即可编译，无需装 VS |
| 主题风格 | 跟随系统明暗（浅/深双色板 + 深色标题栏） | 用户选定；实时跟随系统切换 |
| 版本策略 | 全部做完后压成**单个 V1.0.0 提交**再发布 | 用户要求：减少中间版本，直接验证一个好用的版本 |
| 安装方案 | 便携版 Node（zip 解压到用户目录）+ `npm install -g` | 免管理员权限/UAC 弹窗，对小白最友好 |
| 下载镜像 | npmmirror 优先，nodejs.org 兜底 | 国内网络环境 |
| 状态检测 | netstat 查端口 3080 监听 | 轻量、无 HTTP 请求开销，2 秒轮询 |
| 日志位置 | `%AppData%\npm\dsh-web.log` | 与 dsh 全局安装目录保持一致 |

## 4. 版本路线图

### v1.0.0 —— 已完成（2026-08-14 发布）

- 🧰 **一键安装**：自动检测 Node.js / dsh 缺失，一键下载便携 Node + 安装 dsh
- 🩺 **一键诊断**：环境报告一键生成 + 复制，可贴 GitHub issue 求助
- 🧠 **智能状态**：区分「缺少 Node.js / 未安装 dsh / 运行中(PID) / 已停止」，大按钮语义跟随
- 🎛️ **一键开关**服务（大按钮 + 托盘菜单）
- 🐳 **系统托盘**：关闭窗口最小化到托盘，双击恢复
- 🚀 **自动拉起**：打开时若服务未运行则自动启动
- 🌗 **跟随系统明暗主题**（含深色标题栏、实时切换）
- ⏰ **开机自启开关**（HKCU Run 键，免管理员）
- 📂 **打开界面 / 查看日志**按钮

### v2.1 —— 已完成（2026-08-14 发布，tag v2.1.0）

发布闭环，让"别人真正能用"：

- ✅ **GitHub Actions 自动构建 Release**：打 `v*` tag 即触发 `release.yml`，在 windows-latest 干净环境用 csc 构建 exe + 打包 zip，自动创建 Release 附资产（已端到端验证：v2.1.0 Release 含 exe/zip）
- ✅ **CI 构建检查**：`ci.yml` 每次 push/PR 验证 build.bat 可构建
- ✅ **中英双语**：界面（跟随系统/中文/English，设置可切换）+ README.en.md
- ✅ **设置面板**：语言/主题（跟随系统/浅色/深色）/端口（默认 3080，可改）
- ✅ **issue 模板**：Bug report + Feature request（引导用户贴"一键诊断"报告）
- ✅ **SmartScreen 下载说明**：README 说明未签名 exe 的"仍要运行"操作

### v2.2.0 —— 已完成（2026-08-14 发布，tag v2.2.0）

- ✅ **「一键安装/修复」常驻可见**：界面底部按钮 + 托盘菜单，环境齐全时作为修复重装入口（此前仅在环境缺失时出现，发现性问题）
- ✅ 安装前自动停服务（避免 npm 覆盖运行中文件失败）；环境齐全时用系统 npm 修复，不重复下载 Node

### 远期候选（未排期）

- 内置日志查看器（替换记事本打开）
- 更细的智能修复（端口被占用时提示并引导）

## 5. 发布策略

- **单提交原则**：功能全部完成并验证后再发布，避免频繁的中间版本
- 新仓库（无协作者）允许 `git checkout --orphan` + `--force-with-lease` 压历史；仓库有人使用后不再重写历史，改走 tag + Release
- 提交署名用 GitHub noreply 匿名邮箱（`<你的用户名>@users.noreply.github.com`），不暴露真实邮箱
