# whale-sitter V2.5.0 · 需求文件（2026-09-28 转正实施）

> 依据：《规划/WS-V2.5.0-版本更新计划.md》（DSH 0.1.7 适配 + 体验增强）。
> **开工指令：2026-09-28 用户"按前面充分整理的，来做dsh升级与WS升级"。**
> 本文件 = S 修改点唯一来源；验收执行规范见《验收/WS-V2.5.0-验收标准.md》。

## 0. 红线（本版全局）

1. **不破坏现有安装/修复链路** — 安装流程已稳定，不重构核心路径
2. **零第三方依赖** — 保持仅用 .NET Framework 自带程序集的约束
3. **单文件可编译** — 如果拆分文件，`build.bat` 必须仍能一键编译
4. **向后兼容 dsh 0.1.5+** — token 适配逻辑不回归
5. **先红后绿** — 所有新增功能先写失败测试再实现

## 1. 修改点（S 编号）

### S-01 · DSH 0.1.7 适配（P0 锚点）

| 项 | 内容 |
|---|---|
| 修改点 | 验证 dsh 0.1.7-rc.2 的 token 机制、日志格式、进程管理是否变化；如有变化则适配 |
| 边界 | 只适配不升级本地 dsh（用户自行决定）；不改变安装流程 |
| 依据 | 官方已发 0.1.7-rc.2，本地已升级验证 token 正常 |
| 实测结论 | 0.1.7-rc.2 token 机制未变（`dsh web: http://127.0.0.1:PORT/?token=…`）；插件兼容性检查为新增（优雅拦截不兼容插件） |

### S-02 · 内置日志查看器（P1）

| 项 | 内容 |
|---|---|
| 修改点 | 替换记事本打开，新增内置日志查看器窗口：实时滚动、ERROR/WARN 高亮、关键词过滤、token 自动脱敏 |
| 边界 | 只读展示，不修改日志文件本身；保留"查看日志"按钮（改为打开内置查看器） |
| 依据 | 高频痛点，记事本体验差；TROUBLESHOOTING 记录中排查问题靠记事本翻找 |

### S-03 · 安装进度条（P1）

| 项 | 内容 |
|---|---|
| 修改点 | 解析 npm 输出显示当前步骤（下载 Node → 解压 → npm install → 完成），至少显示步骤名 |
| 边界 | 不改变安装逻辑，只增强反馈 |
| 依据 | 安装时用户不知道进度，体验差 |

### S-04 · 自动更新检查（P1）

| 项 | 内容 |
|---|---|
| 修改点 | 启动时（或每天一次）查 GitHub Releases API，有新版时托盘气泡提示 |
| 边界 | 只提示不自动下载；API 失败静默 |
| 依据 | 用户不知道有新版本 |

### S-05 · 端口占用智能引导（P2）

| 项 | 内容 |
|---|---|
| 修改点 | 检测到端口被占用时，提示占用进程名/PID，引导换端口或一键杀进程 |
| 边界 | 杀进程需用户确认 |
| 依据 | 偶发但排查成本高；ROADMAP 远期候选 |

### S-06 · 托盘菜单状态感知（P2）

| 项 | 内容 |
|---|---|
| 修改点 | 启动/停止项互斥显示（运行中只显示"停止"，停止时只显示"启动"），加勾选标记 |
| 边界 | 不改托盘图标 |
| 依据 | 当前菜单不反映状态 |

### S-07 · 日志轮转（P2）

| 项 | 内容 |
|---|---|
| 修改点 | 安装/修复时备份旧日志为 `dsh-web.log.1`，保留最近 3 份 |
| 边界 | 只在安装/修复时触发，不后台轮转 |
| 依据 | 日志无限增长 |

### S-08 · 诊断报告导出（P2）

| 项 | 内容 |
|---|---|
| 修改点 | 增加"保存为文件"按钮，方便离线发送 |
| 边界 | 格式纯文本 |
| 依据 | 只能复制不便于存档 |
